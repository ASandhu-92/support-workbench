**Customer impact.** One customer (dev.patel@example.com) says the live site logs that MAPS_API_KEY is undefined, so anything that depends on the key is failing in production. Preview works, so they have no workaround on the live site. Nothing in the ticket points to other customers being affected.

**Evidence (quoted from the ticket)**
- MAPS_API_KEY is undefined
- I set MAPS_API_KEY as a Production variable
- it shows in Settings > Environment with the Production tag
- redeployed twice
- Preview works

**Already tried by the customer**
- Set MAPS_API_KEY as a Production variable; it shows in Settings > Environment with the Production tag
- Redeployed twice
- Read the docs about scopes

**KB checked:** KB-08, KB-04, KB-05. KB-08 and KB-04 say a Production-scoped variable is applied on the next deploy, and the customer says they set the scope correctly and redeployed twice, so the documented answer does not explain the value still being undefined.

**Questions for engineering**
- For this customer's project, does the latest Production deploy snapshot include MAPS_API_KEY, and is the stored scope Production?
- Did both redeploys build after the variable was saved, or could they have used a cached or older variable set?
- Is anyone else seeing Production variables missing at runtime after a deploy, or is this limited to this project?
