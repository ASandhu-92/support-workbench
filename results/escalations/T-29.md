# T-29: Production env var MAPS_API_KEY undefined on live site after two redeploys; Preview works

| | |
|---|---|
| Severity | sev2 |
| Customer | dev.patel@example.com |
| Received | 2026-09-22T11:50:00Z |
| Triage | tier 3, environment-variables, urgency normal |
| Suspected area | Injection of Production-scoped environment variables into deploy builds or the runtime of the live app. Possible causes are a scope not saved server-side, a stale cache or snapshot from the deploy, or the app code reading the variable in a way that differs between Preview and Production. |

**Customer impact.** The customer's live site cannot read MAPS_API_KEY, which is set with the Production tag. The customer has told us this blocks the feature that uses the key in production. Preview works. Nothing in the ticket suggests other customers are affected.

**Evidence (quoted from the ticket)**
- I set MAPS_API_KEY as a Production variable
- it shows in Settings > Environment with the Production tag
- redeployed twice
- The live site still logs "MAPS_API_KEY is undefined"
- Preview works

**Already tried by the customer**
- Set MAPS_API_KEY as a Production variable and confirmed it shows with the Production tag in Settings > Environment
- Redeployed twice
- Read the docs about scopes

**KB checked:** KB-04, KB-05, KB-08. KB-04 and KB-08 say a Production-scoped variable is available to the live site after the next deploy, and the customer says they set the scope correctly and redeployed twice, so the documented answer does not explain the value being undefined.

**Questions for engineering**
- For this customer's project, is MAPS_API_KEY stored with Production scope, and was it included in the environment of the two most recent production deploys?
- Do the deploys the customer made after saving the variable use a fresh build, or could they reuse a cached snapshot from before the variable existed?
- Have other projects reported a Production variable that is undefined at runtime while Preview works, to rule out a wider fault?
