# T-28: Blank preview in Safari 19 due to unguarded navigator.gpu.requestAdapter call

| | |
|---|---|

| Customer | lucy.grant@example.com |
| Received | 2026-09-22T09:25:00Z |
| Triage | tier 3, editor-and-generation, urgency normal |
| Suspected area | AI code generation producing code that calls navigator.gpu.requestAdapter without checking for WebGPU support/availability, causing an uncaught TypeError that blanks the preview in browsers/versions where WebGPU is unavailable or unflagged (e.g. this Safari 19 build). |

**Customer impact.** Single customer (lucy.grant@example.com) cannot use the preview pane in Safari 19 on Mac; app works in Chrome so a workaround exists.

**Evidence (quoted from the ticket)**
- The preview pane is a blank white screen in Safari 19 on my Mac. Works fine in Chrome.
- TypeError: undefined is not an object (evaluating 'navigator.gpu.requestAdapter')

**Already tried by the customer**
- Hard refresh
- Private window with extensions off

**KB checked:** KB-01. KB-01 only covers generic blank-preview steps (hard refresh, private window), which the customer already did; the root cause here is generated app code calling a WebGPU API without feature detection, which is a codegen behavior question that needs engineering input, not a documented user fix.

**Questions for engineering**
- Can we pull the generated source for this project to confirm where navigator.gpu.requestAdapter is called and whether there is any feature detection or try/catch around it?
- Should the code generator add a WebGPU availability check (e.g. if (navigator.gpu)) by default whenever it emits WebGPU calls, given inconsistent support across Safari versions?
- Is this limited to Safari 19, or do we need a broader compatibility shim/fallback path in the preview runtime for browsers lacking WebGPU?
