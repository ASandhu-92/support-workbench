**Customer impact.** Customer's live production database shows zero rows after a redeploy that only changed text/copy. Reports roughly 1,200 customer booking records are gone from the live app. Preview database is unaffected.

**Evidence (quoted from the ticket)**
- database empty after redeploy
- only changed some text
- the live database has zero rows
- We had about 1,200 customer bookings in there
- Preview database is fine
- Project is 'grooming-bookings'

**Already tried by the customer**
- Customer redeployed the app expecting only a text change; has not attempted any recovery steps themselves, reporting the issue directly.

**KB checked:** KB-04, KB-11. KB-04 describes deploy as a code/build snapshot and does not document any case where a deploy wipes the production database; this is unexpected behavior, not a documented user error. Recovery requires locating and restoring a daily database snapshot per KB-11, which is a support/engineering action, not self-serve.

**Questions for engineering**
- Can we confirm exact time of last night's redeploy for project 'grooming-bookings' and pull the build/deploy log to check for any migration, reset, or seed command that ran against the production database?
- Can we restore the most recent pre-deploy daily snapshot (per KB-11, 7-day retention) for this project's production database, and confirm how close to last night it is?
- Is there any indication the production DB connection string or scope got swapped with Preview during this deploy, which could explain live having zero rows while Preview is intact?
